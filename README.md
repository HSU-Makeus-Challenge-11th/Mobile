# UMC 11th Mobile 스터디

Flutter / Backend 파트가 주차별 미션을 올리는 레포입니다.
PR을 올리기 전에 아래 컨벤션을 한 번 확인해 주세요.

## 폴더 구조

```
weekNN/
└── 닉네임/
    └── 프레임워크/   # flutter, spring, nestjs ...
```

- 주차는 두 자리로 씁니다. (`week00` ~ `week10`)
- 프레임워크 폴더는 본인이 선택한 프레임워크 이름을 소문자로 씁니다. (`flutter`, `spring`, `nestjs` 등)
- 닉네임은 영문으로 쓰고, 한 번 정하면 모든 주차에서 같은 이름을 씁니다.
- **내 폴더 안의 파일만 수정합니다.** 다른 사람 폴더나 레포 공통 파일은 건드리지 않습니다.
- 이전 주차 코드를 이어서 쓸 때는 새 주차 폴더로 복사하는 커밋을 따로 만듭니다.
  - 예: `chore: 0주차 Flutter 프로젝트를 1주차로 복사`

## 브랜치

```
weekNN/닉네임-프레임워크
```

| 예시 | 설명 |
| --- | --- |
| `week01/Yido-flutter` | 1주차 Flutter 미션 |
| `week03/endl24-spring` | 3주차 Spring 미션 |
| `chore/convention` | 레포 공통 작업 (컨벤션, 템플릿 등) |

- 프레임워크는 폴더 이름과 같이 소문자로 씁니다. (`flutter`, `spring`, `nestjs` 등)
- 주차 · 프레임워크마다 브랜치 1개, PR 1개입니다.
- `main` 에 직접 push 하지 않습니다.
- 이전 주차 PR이 머지되기 전에 다음 주차를 시작해야 하면, 이전 주차 브랜치에서 새 브랜치를 따도 됩니다.

## 커밋 메시지

```
type: 요약
```

| type | 언제 쓰나요 |
| --- | --- |
| `feat` | 새 화면, 새 기능, 새 API |
| `fix` | 버그나 잘못된 내용 수정 |
| `refactor` | 동작은 그대로 두고 코드 구조 개선 |
| `style` | 코드 포맷, 줄바꿈 등 (UI 디자인 변경은 `feat` / `fix`) |
| `docs` | README, 학습 기록, ERD 같은 문서 |
| `test` | 테스트 코드 추가 · 수정 |
| `chore` | 프로젝트 생성, 설정, 패키지 추가, 파일 이동 · 복사 |

- 요약은 한국어로, 명사형으로 끝내고 마침표를 찍지 않습니다.
- 한 커밋에는 한 가지 변경만 담습니다.

```
feat: 내 프로필 화면 구현
fix: 시작 화면 주차 문구 수정
docs: 1주차 백엔드 ERD 설계 추가
chore: Flutter 프로젝트 생성
```

## Pull Request

- **base 브랜치:** `main`
- **제목:** `[N주차/프레임워크] 요약`
  - `[1주차/Flutter] 내 프로필 화면 구현 및 테마 적용`
  - `[3주차/Spring] 회원 API 구현`
- 본문은 PR 템플릿을 채워서 올립니다. 해당 없는 항목은 지워도 됩니다.
- 머지는 **Create a merge commit** 으로 합니다.
  - 다음 주차 브랜치를 이전 주차 브랜치에서 딴 경우, Squash로 머지하면 다음 주차 PR에 이전 주차 변경이 다시 섞여 보이기 때문입니다.

### 리뷰할 때

- 코멘트는 부담 없이, 이유와 함께 남깁니다.
- 꼭 고쳐야 하는 부분이 아니면 앞에 `[제안]` 을 붙여 구분합니다.
- 궁금한 점도 코멘트로 편하게 물어봅니다.

## 올리면 안 되는 파일

- API 키, 비밀번호, `.env` 같은 비밀 값
- `build/`, `.dart_tool/` 같은 빌드 결과물 (`.gitignore` 확인)
